# 케셰브 재현 기록

이 기록은 22단계 재현 점검의 범위와 실제 확인 여부를 남깁니다. 소스 코드만 읽은 결과, 버전 명령 결과, 새 폴더에서 직접 실행한 결과를 구분합니다. 실행하지 않은 동작은 성공으로 기록하지 않습니다.

## 1. 재현 대상과 원본 보존

| 항목 | 기록 |
|---|---|
| 저장소 | `https://github.com/yubin05/kesheb-defense` |
| 브랜치 | `main` |
| 22단계 기록 작업 전 원격 기준 커밋 | `b0f3870b56c068dc28f180912329a73eb12f1700` (21단계 학생 실행 설명서 추가 커밋) |
| 22단계 제출 대상 | 이 문서를 포함해 GitHub `main`에 올라간 최종 커밋. 제출 화면에 입력한 40자리 SHA와 새 폴더에서 `git rev-parse HEAD`로 확인한 값이 같아야 함 |
| 앱 버전 | `package.json`의 `0.2.21` |
| 원래 작업 폴더 | `C:\Users\User\kesheb-defense` — 별도 재현 작업을 위해 유지 |

기록 작업 전 원격 커밋은 확인했지만, 이 커밋을 새 폴더에서 실행하지 않았습니다. 이 문서가 추가된 뒤의 최종 제출 SHA는 위 기준 커밋과 다르며, 아직 별도 폴더에서 검증하지 않았습니다. 원격 제출 대상과 원래 폴더의 로컬 Git 상태는 같지 않습니다. 로컬 `HEAD`는 `d8e036acfa7e437028492c187b37a94586cc0c3f`이고 작업 트리에 미커밋·미추적 변경이 있으므로 이 작업 트리를 깨끗한 재현본으로 취급하지 않습니다. 기존 항목을 정리하거나 원격에 포함하지 않았습니다.

## 3. 새 폴더에서 같은 커밋 재현하기

원래 폴더에서 `git clean`, `git reset`, 설정 파일 복사, 키 복사를 하지 않습니다. 프로젝트 밖의 새 위치를 `$env:TEMP` 아래에 만들고, 제출할 최종 커밋을 그대로 checkout합니다. 대상 폴더가 이미 있으면 삭제하거나 덮어쓰지 말고 새 폴더 이름을 정합니다.

```powershell
$repoUrl = 'https://github.com/yubin05/kesheb-defense.git'
$commitSha = '<제출 화면에 입력할 40자리 최종 SHA>'
$reproPath = Join-Path $env:TEMP 'kesheb-defense-stage22-repro'

if (Test-Path -LiteralPath $reproPath) {
    throw "대상 폴더가 이미 있습니다. 보존하고 다른 새 경로를 선택하세요: $reproPath"
}

git clone --no-checkout $repoUrl $reproPath
git -C $reproPath checkout --detach $commitSha
git -C $reproPath rev-parse HEAD
```

마지막 출력이 `$commitSha`와 글자 단위로 같아야 합니다. 다르면 실행을 진행하지 말고 checkout한 저장소와 제출 SHA를 다시 확인합니다. 비공개 저장소 접근이 거절되면 공개로 바꾸거나 자격 증명을 문서에 적지 말고 공식 과제 화면의 비공개 원문 전달 절차를 따릅니다.

새 폴더에서 `docs/STUDENT_RUNBOOK.md`의 Node.js 버전 확인, 시작 절차, 브라우저 확인, `Ctrl+C` 종료, 재실행을 순서대로 수행합니다. 기존 연결 설정을 복사하지 않습니다. 연결 없는 로컬 화면만 확인할 때는 다음 실행 옵션을 사용하고, 계정 연결·AI 연결 성공으로 기록하지 않습니다.

```powershell
Set-Location $reproPath
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NoNativeHost -Port 5190
```

예상 브라우저 주소는 `http://127.0.0.1:5190/`입니다. 스크립트의 로컬 서버 응답은 외부 시스템 연결이나 계정 판정 성공을 뜻하지 않습니다. 이 문서를 작성할 때 위 `git clone`, 실행, 브라우저 확인, 종료·재실행 명령은 실행하지 않았습니다.

## 4. 재현 관찰 기록

아래 값은 이 문서 작성 시점의 기록입니다. 실제 재현 후 관찰한 값으로 갱신하고, 실제로 본 메시지나 화면 근거만 기록합니다.

| 확인 항목 | 관찰값 |
|---|---|
| 재현 대상 commit SHA | 최종 제출 커밋 SHA와 일치하는지 새 폴더에서 확인할 것 — 미확인 |
| 확인 일시 | 새 폴더 실행을 하지 않음 — 미확인 |
| 환경 | 개발 작업 환경의 버전 명령만 확인. 새 폴더의 환경 확인은 미확인 |
| 설치·실행 출력 | 미확인 |
| 브라우저 표시·주소 | 미확인 |
| 종료·재실행 | 미확인 |
| 실제 계정·SDP·AI·OSV 응답 | 미확인 |
| 미완료 제한 | 19단계 조치의 실제 집행기 연결은 미확인. `pending`은 효과 확인이 아님 |

예제 모드 자료를 확인했다면 `demo`로 표시하고 실제 계정 결과와 분리합니다. 연결 없음·오류·`unknown`은 정상이나 성공으로 바꾸지 않습니다. 22단계 원문 검토는 문서와 코드의 일치 여부를 읽는 판정이며, 서버가 명령을 실행했다는 증거가 아닙니다.

## 5. 데이터 보존·백업·복원

| 데이터 | 보존·복원 방법 | 제한 |
|---|---|---|
| 학생 코드·문서 | 원래 작업 폴더를 보존하고, 제출한 코드는 GitHub의 해당 commit으로 식별합니다. 재현은 새 폴더에 clone해 수행합니다. | 기존 폴더에 `clean`, `reset`, 덮어쓰기를 하지 않습니다. 미커밋 변경은 커밋 원문에 포함되지 않습니다. |
| 개인 연결 설정·자격 정보 | 원래 PC의 승인된 보관 위치에 두고 새 재현 폴더로 복사하지 않습니다. 연결이 필요하면 운영자가 안내한 절차를 사용합니다. | Git·문서·캡처·도움정보에 비밀값을 넣지 않습니다. 이 프로젝트 문서가 자격 정보 백업·복원 기능을 제공한다고 주장하지 않습니다. |
| 접속·XDR 기록 및 OSV 자료 | 제공 서버가 반환하는 범위에서 다시 조회합니다. | 이 저장소에 전체 외부 기록 백업·복원 절차는 없습니다. 재조회 결과가 원래 결과와 같다고 보장하지 않습니다. |
| 조치 영수증·감사 자료 | 조치 기능이 운영 설정된 경우 제공된 기존 SQLite 데이터베이스에 기록될 수 있습니다. DB 백업·복원은 해당 시스템 운영자의 절차를 따릅니다. | 설정되지 않은 경우 조치 기능은 지원되지 않습니다. DB 파일을 재현 폴더로 복사하거나 실제 집행을 시험하지 않습니다. |

복원 범위는 Git에 커밋된 소스·문서입니다. 외부 서버 기록, 개인 자격 정보, 운영 DB를 이 문서나 앱이 자동 백업·복원하지 않습니다. 기존 폴더와 Git 이력을 지우는 복구 절차는 사용하지 않습니다.
